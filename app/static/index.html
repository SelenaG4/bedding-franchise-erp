How this works

Everything below needs an API key in the bar above — run python scripts/seed.py once to create demo accounts and print an admin key plus one key per account. This demo deployment's admin key defaults to dev-admin-key-change-me unless the ADMIN_API_KEY environment variable was set — safe to show here since it's the same public fallback value visible in app/auth.py on GitHub. A real deployment would set a real secret.

1Run production admin key

Turns fabric into finished-goods stock. Leftover fabric becomes a reusable remnant roll automatically, or is recorded as scrap if too short to reuse.

2Place a sales order your account key, or admin

An account key can only place orders for itself — trying another account_id is rejected. Supermarket orders need a PO number; international orders need a customs declaration.

3My orders & receivables your account key, or admin

Shows exactly what the current API key is allowed to see — an account key sees only its own account; an admin key can look up any account ID.

4Plan a production batch admin key

Compares the greedy one-roll-at-a-time heuristic against a jointly-optimal MILP assignment (app/optimization.py) for the same batch of pending production runs. Add a couple of rows with realistic quantities against your current fabric-roll pool to see a difference.

5Reorder-point simulator admin key

Monte Carlo recommendation bootstrapped from synthetic demand history, benchmarked against the textbook Normal-formula answer (app/simulation.py). Needs data/demand_history.csv to have rows for the product ID you enter.

Database schema

Nine tables spanning production, sales, and accounting — fabric remnants link back to their parent roll, and finished-goods stock is always the sum of a movement ledger rather than a raw counter.
